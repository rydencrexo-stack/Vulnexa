Task 01 · Conceptual Overview

The Two Paradigms of Security Scanning

Security scanners discover vulnerabilities using two fundamental methodologies: Passive Observation and Active Probing.

Understanding when to employ each method is essential for balancing security rigor against application availability and business continuity.

Golden Rule

Passive scanning answers: "What misconfigurations are visible in standard traffic?" whereas Active scanning answers: "How does the backend respond when untrusted payloads are injected?"

Task 02 · Passive Inspection

Passive Analysis Mechanics

In passive mode, PAN acts as a non-intrusive analyzer. It crawls reachable pages using standard browser requests and evaluates:

  • Missing Security Headers: Absence of Content-Security-Policy, Strict-Transport-Security, or X-Frame-Options.
  • Insecure Cookie Flags: Cookies lacking HttpOnly, Secure, or proper SameSite directives.
  • Exposed Metadata: Server software version banners (e.g. Server: Apache/2.4.41) and debug stack traces.
Which of the following findings can be reliably identified purely through passive scanning?
Missing HSTS and unencrypted session cookie flags
Blind Time-Based SQL Injection in a login POST handler
Remote Code Execution via deserialization
Task 03 · Active Fuzzing

Active Payload Generation

Active scanning intentionally generates mutated inputs and submits them into query parameters, form fields, JSON bodies, and headers.

For example, to test for SQL injection, the scanner submits ' OR 1=1-- and monitors whether the SQL query semantics are altered.

Why does active scanning carry a higher operational risk than passive scanning?
Active payloads mutate backend data, submit forms, and can trigger server side-effects.
Active scanning cannot run over HTTPS.
Active scanning only works on mobile applications.
Task 04 · HTTP Telemetry Inspection

Evaluating Telemetry Evidence

Inspect the HTTP response headers captured by PAN's scanner below:

HTTP/1.1 200 OK Server: nginx/1.18.0 (Ubuntu) Set-Cookie: session_token=ab98721cda8; Path=/ Access-Control-Allow-Origin: * Content-Type: text/html; charset=UTF-8
What security issue is evident in the Set-Cookie header?
The cookie is missing the HttpOnly and Secure security flags.
The path parameter is invalid.
The token value is too short.
Task 05 · Engine Orchestration

PAN Scanner Pipeline Orchestration

In a production PAN pipeline, passive reconnaissance is executed first to discover endpoints and map surface parameters. Active scanning rules then selectively target high-risk endpoints identified during passive discovery.

What is the advantage of running passive analysis before initiating active payload fuzzing?
It allows the scanner to build an endpoint map and focus active probes on verified attack vectors.
Passive analysis automatically patches the backend code.
It bypasses the need for target scope authorization.
