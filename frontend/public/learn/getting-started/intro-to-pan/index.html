Task 01 · Conceptual Overview

What is PAN?

Modern organizations deploy dozens of domain names, API microservices, web apps, and cloud buckets every week. Traditional static vulnerability scanners miss shadow IT because attack surfaces change dynamically.

PAN is a continuous security platform designed to discover exposed internet assets, analyze vulnerability risk, and automate security verification from an attacker's perspective.

Core Mission

PAN bridges the gap between passive asset discovery and active vulnerability auditing, providing unified visibility across the entire attack surface.

Task 02 · Lifecycle Flow

The PAN Security Lifecycle

PAN organizes security operations into a sequential, reproducible 9-step lifecycle:

TARGET → RECON → ASSETS → ENDPOINTS → SCAN → FINDINGS → ANALYSIS → REMEDIATION → RETEST

This flow guarantees that vulnerability scans are conducted only on validated assets and endpoints discovered during the reconnaissance phase.

Task 03 · Workspace Organization

Workspaces & Target Scope

A Workspace in PAN acts as an isolated project container for a specific organization or environment (e.g. Staging Environment vs Production E-Commerce).

Within a workspace, users define Targets by specifying root domain names (e.g. pan-demo.io) and scope rules to keep scanning strictly bound to authorized targets.

Task 04 · Probing Mechanics

Reconnaissance vs Vulnerability Scanning

PAN distinguishes between passive reconnaissance and active vulnerability scanning:

  • Reconnaissance: Queries public Certificate Transparency (CT) logs, DNS records, and WHOIS databases without sending disruptive traffic to target servers.
  • Vulnerability Scanning: Sends targeted HTTP payloads to endpoints to verify XSS, SQLi, IDOR, SSRF, and XXE flaws.

Task 05 · Actionable Results

Findings, Analysis & One-Click Retesting

When a scan completes, PAN aggregates vulnerabilities into structured Finding Objects complete with CVSS score ratings, confidence scores, and raw HTTP evidence.

After engineers deploy code fixes, PAN's One-Click Retest replays the exact exploit request to verify that the vulnerability is safely resolved.

Why is One-Click Retesting critical after software developers deploy a security patch?
It confirms that the patch successfully fixed the flaw without requiring a full system rescan.
It deletes all server log entries.
It automatically writes unit test code.
