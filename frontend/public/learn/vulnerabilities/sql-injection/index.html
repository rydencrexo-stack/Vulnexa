Task 01 · Vulnerability Foundations

What is SQL Injection?

SQL Injection (SQLi) is a critical web vulnerability that occurs when untrusted user input is directly concatenated into a dynamic database query string.

This allows an attacker to manipulate the query structure, bypass authentication, exfiltrate sensitive data, modify records, or execute administrative commands.

Root Cause

SQL injection occurs when the database engine fails to differentiate between SQL code instructions and user data parameters.

Task 02 · Injection Classifications

In-Band, Error-Based & Blind SQLi

SQL Injection vulnerabilities are categorized by how the attacker extracts data:

  • In-Band (UNION-Based): The attacker uses the same channel to inject payloads and view extracted table rows in the HTML response.
  • Error-Based: The attacker intentionally triggers database exceptions (e.g. syntax error in query) to read extracted data in error messages.
  • Blind (Boolean & Time-Based): No data is visible. The attacker infers data character-by-character by observing true/false response differences or database sleep delays (e.g. pg_sleep(5)).

Task 05 · Defensive Architecture

Parameterized Queries & Prepared Statements

The primary defense against SQL Injection is using Parameterized Queries (Prepared Statements).

When using prepared statements, the database driver compiles the SQL query structure first with placeholders (e.g. $1 or ?), and treats incoming user inputs strictly as literal values.

Which code pattern correctly remediates SQL injection in Node.js pg client?
client.query('SELECT * FROM users WHERE id = $1', [userId])
client.query('SELECT * FROM users WHERE id = ' + escape(userId))
client.query(`SELECT * FROM users WHERE id = ${userId}`)
