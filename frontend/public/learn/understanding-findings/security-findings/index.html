Task 01 · Findings Structure

Anatomy of a Security Finding

When an automated engine discovers a vulnerability, PAN generates a structured Finding Object containing:

  • Finding Title & Type: Normalized CWE/OWASP vulnerability identifier.
  • Target Asset & Endpoint: Fully qualified domain, port, HTTP method, and parameter name.
  • Severity Rating: Critical, High, Medium, Low, or Informational.
  • Confidence Score: Deterministic Proof, High, Medium, or Tentative.
  • Reproducible Evidence: Raw HTTP request with injection payload and matched response snippet.
Task 02 · Metrics & Scoring

Understanding Severity vs Confidence

Severity measures the potential business and technical impact if the flaw is exploited. Confidence measures how certain the scanner is that the issue is genuine rather than an anomaly.

Key Triaging Rule

A Critical Severity issue with Tentative Confidence should be manually verified before alerting emergency on-call teams.

If a scanner detects database SQL syntax errors reflected directly in response HTML, what confidence level does PAN assign to the SQL Injection finding?
Confirmed / High Confidence (Direct evidence proof)
Tentative / Low Confidence
Informational Only

Task 04 · Noise Reduction

Triaging False Positives

A False Positive is an alert triggered by a scanner for a vulnerability that does not actually exist.

Common false positive causes include custom error pages returning HTTP 200 instead of 404, or generic WAF block pages echoing user payloads without browser execution context.

What is the standard triaging status in PAN when an analyst verifies that an alert is an intentional security control rather than a defect?
Mark as False Positive / Accepted Risk
Delete Target Entirely
Escalate to Critical

Once developers deploy a code fix, PAN offers a One-Click Retest button. The scanner replays only the exact HTTP transaction that originally produced the finding to confirm that the vulnerability is resolved.
